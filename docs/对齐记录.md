# 与 NameDayMascot 的对齐记录

对照对象：`NameDayMascot-CSharp-src.zip`（2026-11-07 版）。
做法：以它为新基座整体替换，再把「柏林以东」需要的适配合并进去。

## 一、继承下来的能力（这次是重点）

### 渲染与窗口几何

| 机制 | 实现位置 | 作用 |
|---|---|---|
| 逐帧 49 帧采样 + 分位保护 | `SkeletonModel.ComputeBounds` | 采样太稀会让快速摆动的极值落在两点之间，静态框偏小 → 渲染超出窗口。分位框只在绝对框被撑到 2.2 倍以上时启用 |
| 绘制比例与窗口解耦 | `PetRenderControl` | 比例只由「用户缩放 × DPI」决定，不再按窗口尺寸反算，避免 resize → 比例变 → 视框变的反馈环 |
| 视框对称扩张、收缩延迟 | `PetRenderControl.DynamicView` | 当前帧顶点对称扩张立即生效，收缩延迟 1 秒，动作大时窗口长大、结束后缓慢缩回 |
| 底边中点锚定 | `PetWindow.ApplySizeKeepingBottom` | resize 时脚底不动，只往上长，不会再出现 ΔH/2 偏移 |
| 角色锚点 | `SkeletonModel.AnchorX/AnchorY` | X 取「头部带」顶点 x 中位数（不被单手持剑拖偏）；Y 取待机动画顶点 y 的 2% 分位（跳过脚下特效）。渲染时该点固定在「水平中心 + 距下沿 12 DIP 常数」 |
| 布局同步 | `UpdateLayout()` + 统一取整 | 先强制布局再移位置，消除 resize 后一两帧用旧 Bounds 画出来的偏移 |
| 不钳制 | 删除全部 ClampToScreen | 窗口可拖到屏幕外、接触边缘不回弹；吸附默认关闭 |
| 启动救援 | `EnsureOnScreen` | 露出一个像素就算还在屏上；完全不在屏上才放回右下角 |
| 换肤不播 born | `PlayIntro(withBorn: false)` | born 是「从画面外飞入、从地面升起」，换肤时播会像在往左上偏 |

### 界面与配置

- 皮肤自动扫描 `Assets/characters/`，不再硬编码列表；显示名三级兜底：内置名 → `display.txt` → 目录名；资源缺失置灰不可选
- 皮肤独立成卡片网格 Tab，缩略图运行时渲染后缓存到 `%AppData%/BkornblumeMascot/thumbs`
- 按键绑定可视化编辑：两行卡片、动画名下拉、chip 标签、非法格式标红、一键恢复默认
- 托盘与右键菜单都能切换皮肤 / 播放动作 / 重置位置 / 隐藏 / 退出
- 单实例：二次启动唤醒已运行实例（`EventWaitHandle`，Linux 不支持时记日志后忽略）

### 动作逻辑

- 定时随机动作默认 20 秒，5~180 秒可调、可关；任何手动动作都重置计时
- 随机池排除 `idle / born / sleep / die / posture`；连续两次不重复
- **定时随机与「点击动作」配置解耦**：点击按配置播，定时器完全忽略该配置

### 工程

- `Spine/.editorconfig` 按目录关闭诊断（`<Compile Update>` 里写 `<Nullable>disable</Nullable>` 是无效写法），配 `NoWarn` 兜底
- csproj 嵌入 `app.manifest`（PerMonitorV2 必需）、`SatelliteResourceLanguages=zh-Hans`、`IncludeNativeLibrariesForSelfExtract`（uiohook.dll 进单文件）、Release 不生成 pdb

## 四、渲染修补：用数据定案（2026-11-07 第四轮）

前两轮都在猜"位移在哪"，猜错了两次：
- 第一轮猜"帧包围盒每帧波动"→ 加了帧内平移夹取（快追踪），结果把"被裁一帧"变成"角色在窗口里晃"；
- 第二轮猜"root 骨骼被整体平移"→ 加 `root.X - root.Data.X` 补偿，一点用都没有。

### 4.0 实测数据（这次不是猜的）

用 `node` + `@esotericsoftware/spine-core@4.2.36` 直接读 `.skel`，在 JS 里复现了
C# 侧 `ComputeBounds` / `ComputeAnchor` / `TryGetFrameBounds` 的全部算法，得到：

```
静态绝对框 1231x354   分位框 263x286   ← 4.68 倍，分位保护生效
AnchorX = -6.7   AnchorY = 11.0
窗口 66.0 x 113.9 DIP（Scale 0.17）

动画          帧包围盒中心相对静态框的最大偏移
unique_1      912      ← 整体平移，跑到 x≈-1000
unique_2      749      ← 同上
die            93
skill2_1       64
unique         46
born           39
其余          ≤36
```

两个关键事实：

1. **位移只在 unique_1 / unique_2**，`born` 完全正常（偏移 39）。前两轮一直盯着 born，
   方向从一开始就错了。
2. **位移不挂在 root 上**。逐帧打印骨骼：`root local(0,0)` 恒为零，
   真正被写的是 root 的儿子 `bone`（`local(-1072,0)`），躯干骨 `..._z_qugan` 还再叠一层。
   所以 `root.X - root.Data.X` 永远是 0 —— 上一轮的补偿代码等于空转。

### 4.1 修法：只抵消「大幅度整体位移」

`SkeletonModel.DriftOffset(x0,y0,x1,y1)`：

```
偏移 = 当前帧包围盒中心 − 静态包围盒中心
补偿 = |偏移| > 70 ? 偏移 − sign(偏移)×70 : 0
```

- **为什么不看单根骨骼**：位移同时写在 `bone` 和躯干骨上，任取一根都补不准；
  包围盒中心直接反映"角色整体画到哪去了"，是这层信息最可靠的近似。
- **为什么要阈值**：70 正好落在实测断层里（unique_1/2 是 912/749，其余最大 93）。
  阈值内的位移属于正常表演，原样保留，否则挥手、倒下都会被拉直，角色变得很僵。
- **补偿后实测 needW**：unique_1 155（静态框刚好 155，**窗口一次都不用变**）、
  unique_2 192、die 213，全部 ≤ 1.5 倍上限 233。

绘制侧在 `RenderFrame` 里 `canvas.Translate(-driftX, -driftY)`，
视框统计侧用同一个 drift 扣掉再算 —— 两边同一口径，视框就不会被远处帧撑爆。

### 4.2 震动：根因是「连续 resize」，不是几何

`PetWindow.OnSizeTick` 的逻辑是"变化超过 2 DIP 就 resize"，而基准的视框收缩是
**逐帧插值**（每帧 12%，约 30 帧）。两者一凑：

- 每个动作播完 → 连续 30 帧视框都在变小 → 30 次 resize
- 每次 resize 都要 `UpdateLayout()` + 改 `Position`
- 在 Windows 上就是肉眼可见的窗口边缘持续抖动，角色也跟着抖 1px 级

改法（两处，都很小）：

| 位置 | 改动 |
|---|---|
| `PetRenderControl.UpdateView` | 收缩改成「延迟 1.2 秒 + 一次到位」，不插值。每个动作最多 1 次扩张 + 1 次收缩 |
| `PetWindow.ResizeKeepingAnchor` | 底边中点用 `double` 算再 `Math.Round`，替掉整数除法 `oldPxW / 2`（奇偶切换会截掉半像素，连续 resize 时左右各抖 1px） |
| `PetWindow.OnSizeTick` | 回滚到基准原版（阈值 2 DIP，不量化、不限频）。上一轮加的 8% 量化会让窗口一次跳 5 DIP，反而更明显 |

### 4.3 上一轮加的东西全部删除

| 删除项 | 删除原因 |
|---|---|
| `_panX/_panY` + `UpdatePan` 帧内平移夹取 | 快追踪周期性超窗 = 高频抖动；且位移已经被 drift 抵消，用不上 |
| `root.X - root.Data.X` 补偿（绘制 / 帧框 / 静态框 / 锚点四处） | root 恒为 0，纯空转 |
| 透明槽位过滤（`slot.A <= 0.001`） | 实测远端隐藏槽位不存在，263x286 的静态框本来就准；加上它反而多一个变量 |
| 尺寸量化 / 6 DIP 迟滞 / 80ms 限频 | 制造了"一跳 5 DIP"的新抖动 |
| 阶梯收缩（每 200ms 降一档） | 同样属于连续 resize |

现在 `PetRenderControl.cs` 与基准的差异只有三处：`_driftX/_driftY` 字段、
`RenderFrame` 里一行 `Translate(-_driftX, -_driftY)`、`UpdateView` 里的 drift 计算 + 一次到位收缩。

### 4.4 验证顺序

1. 待机 10 秒 → 窗口尺寸应该一动不动（needW 89 < 155，完全不扩张）
2. `Ctrl+Q` 连按（unique）→ unique / unique_1 / unique_2 轮换；**unique_1 时角色应该原地播，不再跑到窗口外**
3. `Ctrl+D`（die）→ 窗口可能长一次，然后 1.2 秒后一次性收回
4. 托盘/右键菜单 → 16 个动画都在，带中文名
5. 全程不应该出现窗口边缘的连续抖动

## 五、第五轮：素材恢复原始 + 窗口高度那个 1.8 倍（2026-11-07）

第四轮改完 data 层面的东西（drift 补偿）之后，反馈仍然是"没修好"。这轮换了思路：先怀疑素材，再怀疑代码，不再靠推理。

### 5.0 素材：全部恢复成 uttu 原始文件

之前用的是 **webp → png 转换 + 手工改 atlas 首行贴图名** 的版本。这轮直接从
`https://model.merui.net/chibi/{id}/{id}.{skel,atlas,webp}` 重新拉了原始三件套：

| 素材 | 处理 |
|---|---|
| `.skel` | 原始二进制，逐字节未改 |
| `.atlas` | 原始文本，**首行贴图名保持 `302001.webp`，不再改成 png** |
| `.webp` | 原始图集，**不再转 png**（SkiaSharp 的 `SKCodec` 原生支持 webp） |

顺带确认了一件对整个项目很关键的事：**这套模型的 54 个可见附件 100% 是 `MeshAttachment`**，
UV 是烘焙在 `.skel` 里的整页归一化坐标。也就是说：

- atlas 里的 `rotate: 90/180/270` **完全不影响渲染几何**（只影响 `RegionAttachment`，这里一个都没用）
- 贴图是 webp 还是 png 也不影响几何，只影响采样

所以"素材转换"从来不是几何问题的根源 —— 但保持原始文件仍然是对的：少一层转换就少一个变量。

### 5.1 这次怎么验证的（不用编译、不用开 GUI）

两个离线工具，都在 `tools/probe/`：

1. **`render.js`** —— 用官方 `@esotericsoftware/spine-canvas` runtime 真渲染一帧 PNG。
   用来回答"素材本身对不对"。注意要设 `renderer.triangleRendering = true`：
   这套模型全是 MeshAttachment，而 `drawImages()` 只画 RegionAttachment，不设就渲染出全空。
2. **`dump.js` + `rasterize.py`** —— node 导出每帧的顶点/UV/三角/颜色，
   Python 按 C# `RenderFrame` 的变换链（`translate(pw/2, groundPx)` → `scale(s,-s)` →
   `translate(-ax,-ay)` → `translate(-drift)`）自己光栅化。

结论两条：

- **官方 runtime 渲染出来的角色完全正常**：无花屏、无部件错位、无颜色异常 → 素材没问题。
- **按 C# 变换链光栅化的结果也完全正常** → 渲染器（顶点/UV/三角/混合）没问题。

那问题只能在窗口尺寸。

### 5.2 真 bug：`DesiredPetSize` 的高度乘了 2

```csharp
double w = _halfW * 2.0 * Scale;   // 锚点在水平正中 → 左右各 halfW，乘 2 正确
double h = _halfH * 2.0 * Scale;   // ← 错：锚点是「脚底」，只朝头顶一个方向长
```

`_halfH` 的定义是「锚点到最远边的距离」。渲染时锚点被钉在窗口下沿上方 `GroundInset` 处，
角色**只往上长**，所以窗口高度只需要 `_halfH`，下面的 `2 *` 等于在脚底下预埋了一整份角色高度。

实测量化（Scale 0.17，scaling 4 渲染）：

| 算法 | idle 窗口 | 角色实际占用 | 空白占比 |
|---|---|---|---|
| 当前 `2*halfH` | 264 × 456 | y 226~417（下半 190px） | **50%** |
| 修正 `halfH` | 264 × 252 | y 22~213（几乎填满） | ~3% |

这块空白是透明的，看不见，但它会：挡住鼠标、让角色看起来"偏下/被裁"，
并且让"窗口跟随动作"的每次 resize 幅度都被放大一倍。

改成 `h = _halfH * Scale` 之后，五个代表性动画全部落在窗口内：

```
动画       窗口(px)     内容 bbox              needW   drift
idle       264x252     (89,22)-(187,213)        82     (0,0)
unique_1   264x274     (26,25)-(173,201)       155     (-842,0)
unique_2   264x252     (87,26)-(236,213)       154     (0,0)
born       264x252     (70,24)-(191,213)        90     (0,0)
die        264x252     (105,72)-(232,223)      147     (0,0)
```

注意 `unique_1` 那一行：`drift = -842` 是第四轮的整体位移补偿在起作用，
补偿后 needW = 155，正好等于静态半框 —— **播放 unique_1 时窗口一次都不用变**。
不补偿的话 needW = 997，窗口最多只能到 233，角色会跑到窗口外面 4 倍远处。
